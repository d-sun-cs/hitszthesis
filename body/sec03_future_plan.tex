\begin{semiQuotList}
    \item 持续整理和完善已完成的学术论文工作，补充必要实验，进一步提升报告结论完整性与整体说服力。
    \item 深化对已有四项系统级优化（CFWP、NMA、EPM、TPS）生效机理的验证：在原有端到端吞吐与消融实验之外，补充直接刻画各优化点作用机制的细粒度实验，详见第一点说明。
    \item 扩展系统级实验场景：补充CPU多线程并发编解码实验，在云平台上搭建更大规模的分布式存储集群，并探索向LRC局部恢复相关场景延伸，验证优化方法在更接近生产环境和更多纠删码形态下的适用性。
    \item 在现有FastTT编解码实现基础上，验证小规模覆盖写场景下的增量更新方法，详见第二点说明。
    \item 系统整理研究成果，撰写硕士毕业论文并准备答辩。
\end{semiQuotList}

\subsection{第一点：已有系统优化的机理验证与实验深化}

现有学术论文主要通过端到端吞吐量与消融（Ablation）实验，从结果层面验证了四项优化（缓存友好窗口划分CFWP、相邻合并访问NMA、统一解码抽象EPM、遍历模式选择TPS）带来的整体性能提升。
后期拟在此基础上补充更直接刻画各优化点\emph{作用机制}的细粒度实验，使“为何有效”与“有效多少”都得到充分支撑，并作为后续实验补强的主要依据。

\textbf{缓存命中率验证（对应CFWP）。}
缓存友好窗口划分的核心收益在于提升缓存局部性，但现有实验仅以吞吐间接反映。
后期拟借助\texttt{perf}或Cachegrind等工具直接采集L1/L2/LLC（末级缓存）的缓存命中率与缺失率（Cache Miss Rate），对比开启/关闭窗口划分及不同窗口大小$W$下的指标变化，直接证明缓存局部性的改善，并据此印证窗口大小取值的合理性。

\textbf{内存访问量与写放大验证（对应NMA）。}
相邻合并访问的理论收益是将校验块写入访问量约减半。
后期拟通过访存计数（如\texttt{perf}内存事件或插桩统计）测量编码过程中对数据块、校验块的实际读写次数，验证其与理论复杂度$\Theta((k+\tfrac{km}{2})l)$的吻合程度，量化写放大（Write Amplification）的降低幅度。

\textbf{冗余访存消除验证（对应EPM）。}
统一解码抽象通过将数据块解码与校验块修复融合，省去独立的校验块修复阶段。
后期拟对比统一解码流程与“解码＋独立修复”两阶段流程的总访存次数与遍历轮数，量化被消除的冗余内存访问，直接解释EPM带来约一倍解码性能提升的来源。

\textbf{单块丢失快路径验证（对应TPS）。}
遍历模式选择针对最常见的单块丢失场景采用纵向单遍异或快路径。
后期拟分别统计单块丢失与多块丢失场景下的访存模式与每码字访问次数，验证快路径“每码字恰好访问一次”的特性，并测量流式（Streaming）指令绕过缓存所带来的额外收益。

\textbf{实验维度扩展。}
配合上述机理验证，后期将补充不同块大小、$(k,m)$配置与丢失模式下的细粒度数据，并针对$(10,4)$等不利配置分析瓶颈。
系统侧进一步增加CPU多线程并发编解码、Amazon云平台多节点Ceph集群和LRC局部恢复场景测试，分别考察多核扩展能力、真实网络/磁盘/恢复流程下的端到端表现，以及局部校验组恢复、降级读等负载中移位异或结构的适用边界。

\subsection{第二点：小规模覆盖写下的Two-tone/FastTT增量更新}

已有工作主要验证了FastTT在完整编码、完整解码和Ceph端到端PUT场景中的性能。后期拟进一步关注一种更具体的存储系统写入：已有对象中只有一小段数据被覆盖修改时，如何只更新受影响的数据段和校验段，从而避免不必要的整条条带完整重算开销。

\textbf{问题定位。}
在Ceph等纠删码存储系统中，RBD、CephFS和librados可以对已有RADOS对象的指定偏移和长度写入数据。
这类写入不是新建小对象或顺序追加，而是覆盖已有对象中的一小段内容。
数据段被修改后，相应校验段必须同步更新；若每次都重新处理完整条带，未变化的数据也会参与计算和访存，容易带来明显的额外系统开销。

\textbf{技术思路。}
当一小段旧数据被新数据覆盖时，可先计算变化量$\Delta=old\_data\oplus new\_data$，再把$\Delta$并入对应校验段。
传统Reed-Solomon码也能做增量更新，通常需要将$\Delta$乘以有限域系数后更新校验段；Two-tone码的更新位置由移位偏移决定，找到偏移后的区间后主要执行XOR。
因此，这一工作要验证的是：在同样支持增量更新的前提下，Two-tone/FastTT能否凭借“偏移区间映射+XOR”减少局部覆盖写中的计算和内存访问开销。

\textbf{主要困难与挑战。}
后期工作的重点不是简单写出$\Delta=old\_data\oplus new\_data$，而是把Two-tone的移位异或结构放到真实局部写和读-改-写（RMW）路径中验证。
围绕这一研究方向，需要重点解决以下三项困难与挑战：
\begin{closeItemize}
    \item \textbf{连续写入到移位后校验区间的映射与边界处理。} 客户端只给出对象偏移和写入长度，后端却要定位到数据块、条带/窗口、校验块和移位后的校验偏移。一次小覆盖写可能跨越多类边界，因此需要拆成若干规范化更新任务，分别处理头尾非对齐区间和中间可向量化区间。
    \item \textbf{增量更新与完整重新编码的自适应选择。} 增量更新处理范围小，但需要读旧数据、读旧校验并写回新数据和新校验；完整重新编码处理范围大，但访问更连续、SIMD利用率可能更高。后期需结合更新大小、条带大小和$(k,m)$配置确定两条路径的切换条件。
    \item \textbf{瓶颈定位与ISA-L Reed-Solomon增量更新的公平比较。} ISA-L Reed-Solomon也支持增量更新，不能将Two-tone/FastTT增量更新与Reed-Solomon完整重新编码直接比较。后期需在纯计算层、RMW读写层和可能的Ceph端到端层比较移位异或与有限域乘加的开销，明确适用边界和瓶颈来源。
\end{closeItemize}

具体工作进度安排为：
\begin{closeItemize}
    \item 2026年7月 -- 2026年10月：整理FastTT实现、Ceph集成和已有实验结果，补充缓存命中率、访存次数等机理验证；实现小规模覆盖写增量更新原型，完成移位后校验区间映射、边界拆分及与完整重新编码路径的初步比较。
    \item 2026年11月 -- 2027年2月：完善相邻区间合并、对齐和SIMD XOR等实现细节，补充与ISA-L Reed-Solomon增量更新的分层对比，整理不同写入范围与$(k,m)$配置下的切换条件；若原型稳定，开展Ceph partial write小规模端到端验证，并规划CPU多线程、云平台集群与LRC局部恢复测试。
    \item 2027年3月 -- 2027年5月：完成硕士毕业论文主体撰写、图表整理、格式检查、定稿和答辩材料准备。
\end{closeItemize}
